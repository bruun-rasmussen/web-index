## Commands

```sh
mvn test -Dtest=LuceneIndexTest                         # one test class
mvn test -Dtest=LuceneIndexTest#testLettersDigitsSplit  # one test method
```

Release commits are generated by `maven-release-plugin`; don't write them by hand.

## Architecture

- **`LuceneIndex`** is the public API. It owns the analyzers and both custom token filters.
- **`LuceneHelper`** is package-private. It does the regex and accent normalization that runs on indexed values and queries before Lucene sees them. It also escapes Lucene special characters in queries.

### Analyzer chain

`LuceneIndex.analyzer()` builds one index analyzer and one query analyzer per locale. They differ only in the last step:

StandardTokenizer → StandardFilter → LowerCase → Stop → `SubstitutionFilter` (exceptions) → Snowball stemmer → `AliasFilter` (generalizations, **index-time only**)

- `SubstitutionFilter` replaces a token in place.
- `AliasFilter` adds extra tokens at the same position and follows alias chains. Its keys are matched after stemming, so entries must be written in stemmed form.
- Word lists are loaded through the **context classloader**. The copies under `src/test/resources/lucene/` are used only by the tests.

### Tests

`LuceneIndexTest` builds a RAM index from a YAML fixture, `src/test/resources/dk/es/lucene/sample_da.yaml`. The fixture maps each item id to a list of `{field: text}` maps, and the language comes from the `_da` filename suffix. The tests assert hit counts, so adding fixture items can break existing tests.
